# OctoAcme Project Management Docs — README

Welcome to the OctoAcme Project Management documentation hub. This directory contains standardized processes, templates, and guidance for running projects at OctoAcme.

## Overview

OctoAcme uses a structured project management approach designed to keep work customer-focused, measurable, and collaborative. The program process docs define how teams initiate work, plan delivery, track execution, manage risk, release features, and learn from each milestone.

The operating model emphasizes:
- Customer-first decision making
- Iterative delivery of small, testable increments
- Clear ownership across project roles
- Data-informed execution and continuous learning
- Transparent communication and escalation paths

## Core Principles

OctoAcme projects are:
- Customer-first: prioritize customer value and usability
- Iterative: deliver small, testable increments
- Owned: each project has a named Project Manager and Product Lead
- Data-informed: measure impact and iterate based on evidence
- Psychologically safe: encourage feedback and learning

## Quick Process Summary

OctoAcme manages work through a repeatable lifecycle:

1. Initiate: confirm the problem, stakeholder alignment, and initial scope.
2. Plan: break work into manageable increments with clear acceptance criteria and milestones.
3. Execute: run delivery in short, visible cycles with daily coordination and continuous quality checks.
4. Communicate and manage risk: track blockers, dependencies, and stakeholder updates.
5. Release and learn: deploy with verification, then capture improvements for the next cycle.

## Key Artifacts Used Across Projects

- Project Charter / One-pager
- Roadmap and release plan
- Sprint or iteration backlog
- Acceptance criteria and Definition of Done
- Risk register
- Retrospective notes and action items
- Project board with status tracking

## Communication Cadence

- Weekly sync between PM and Product Lead
- Twice-weekly standups for delivery teams
- Monthly stakeholder updates
- Ad-hoc escalations for blockers and risks
